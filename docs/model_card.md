## 1. 模型概况

| 项 | 内容 |
|----|------|
| 名称 | GraphForge Link Prediction Pipeline |
| 任务 | 图链接预测（Link Prediction） |
| 核心算法 | **node2vec**（Grover & Leskovec, KDD 2016）—— 二阶偏置随机游走 + Skip-Gram Negative Sampling |
| 边特征算子 | Hadamard（默认）/ Average / Weighted-L1 / Weighted-L2 / Concat |
| 下游分类器 | LogisticRegression（sklearn lbfgs，缺失时降级纯 numpy IRLS/Newton） |
| 实现 | 纯 numpy / scipy / sklearn / networkx / optuna；**不使用 torch、torch-geometric、gensim** |
| 预训练权重 | 无（无需任何联网下载） |

> 本项目是经典方法的忠实工程实现，**没有**引入任何自研「新 SOTA」结构。

## 2. 基准结果（benchmark.json，5 seeds，真实运行）

所有数字由 `python examples/run_demo.py` 实际运行产生并写盘后读回校验，无手填值。

| graphforge-node2vec+heur | 5 | 0.6602 ± 0.0060 | 0.6445 ± 0.0057 |
| deepwalk(p=q=1) 消融对照 | 5 | 0.6550 ± 0.0094 | 0.6430 ± 0.0048 |
| katz | 5 | 0.6356 ± 0.0140 | 0.6206 ± 0.0124 |
| spectral | 5 | 0.5558 ± 0.0094 | 0.5663 ± 0.0117 |
| adamic_adar | 5 | 0.5304 ± 0.0067 | 0.5238 ± 0.0041 |
| resource_allocation | 5 | 0.5304 ± 0.0067 | 0.5229 ± 0.0044 |
| jaccard | 5 | 0.5303 ± 0.0068 | 0.5244 ± 0.0071 |
| common_neighbors | 5 | 0.5302 ± 0.0068 | 0.5214 ± 0.0052 |
| preferential_attachment | 5 | 0.5034 ± 0.0154 | 0.5059 ± 0.0066 |
| random | 5 | 0.4979 ± 0.0044 | 0.5012 ± 0.0030 |

**性能门按双口径同时呈现**（裁定见 `../spec/baseline_ruling.md`，Katz 属补充参考基线 reference，不属 node2vec 论文口径公平基线族）：

- **口径 A（主门，node2vec 论文口径基线 CN / Jaccard / AA / PA / 谱方法）**：本系统 0.6731 ± 0.0063 vs 最强局部启发式 spectral 0.5558 ± 0.0094 → **ΔAUC = +0.1173**，std 闸门 0.0079 → ✅ 显著（远超 0.03 门槛）。
- **口径 B（含 Katz，reference 基线）**：本系统 vs katz 0.6356 ± 0.0140 → **ΔAUC = +0.0375**，std 闸门 0.0101 → ✅ 显著（两项闸门均通过）。

| 对比口径 | 最强基线 | ΔAUC | std 闸门 0.5·(σ₁+σ₂) | 绝对增益 | 结论 |
|----------|----------|------|----------------------|----------|------|
| 口径 A（论文口径） | spectral 0.5558 | **+0.1173** | 0.0079 | 0.1173 | ✅ 显著 |
| 口径 B（含 Katz） | katz 0.6356 | **+0.0375** | 0.0101 | 0.0375 | ✅ 显著 |

相比其余局部启发式（CN / AA / RA / Jaccard / PA）：ΔAUC **+0.1049 ~ +0.1697**，均远超闸门。

## 3. 消融实验

| 场景 | 对照（DeepWalk p=q=1） | 处理（HPO 偏置 node2vec） | ΔAUC | 结论 |
|------|----------------------|--------------------------|------|------|
| SBM-700 | 0.6550 | 0.6731 | +0.0181 | 偏置游走有效，但未达 0.03 显著门槛 |
| Karate | 0.7937 | 0.8187 | +0.0250 | 偏置游走有效，未达 0.03 显著门槛 |

HPO（Optuna TPE，仅用 train/valid，6 + 4 trials）选出的参数：

| 场景 | p | q | dim | valid AUC |
|------|---|---|-----|-----------|
| SBM-700 | 1.474 | 0.372 | 32 | 0.6665 |
| Karate | 1.499 | 0.841 | 64 | 0.6875 |

解读：两组都选中 **q < 1（鼓励向外探索 / DFS 式游走）**，与 node2vec 论文「q<1 时更接近广度扩展、覆盖跨社群结构」的结论方向一致；p 略大于 1 抑制原地回退。

第二组消融（离线兜底）：`graphforge-node2vec` vs `graphforge-node2vec(tier1)`（纯 numpy LR + 纯 numpy 指标）在 SBM-700 上 ΔAUC = +0.0110 —— **降级只损失约 1 个 AUC 点**，离线路径可用。

## 4. 典型失败案例（含归因）

`benchmark.json` 每个 seed 各记录 2 条误报 + 2 条漏检（主场景共 20 条）。三类典型模式：

| 类型 | 现象 | 归因 |
|------|------|------|
| 漏检（false negative） | 真实边的打分低至 0.02，两端在训练图中共同邻居 = 0 | 该边被物理删除后两端失去全部一阶共现，游走无法建立关联 —— **跨社群 / 长程边系统性漏检** |
| 漏检 | 端点度数极低（deg ≤ 4） | 低度节点被游走访问次数不足，嵌入估计方差大 —— **低度节点边漏检** |
| 误报（false positive） | 非边打分 0.87，共同邻居 1~2，两端度数中等 | 两端落在同一社群的嵌入相似区，局部与全局证据都不足以区分 —— **同社群内的「嵌入相似度噪声区」误报** |

工程含义：若要继续提升，应优先处理「跨社群长程边」与「低度节点」两类，而非继续堆训练量（实验显示增加 epoch / 增加游走条数反而下降，见第 5 节）。

## 5. 敏感性说明（重要，避免过度解读）

在同一套基准上做过的参数敏感性实测（结论均为实测，非推测）：

| 维度 | 观测 |
|------|------|
| epochs | **1 个 epoch 最优**；2/3/5/8 epoch 的 loss 持续下降但 test AUC 反而下降 0.01~0.02（SGNS 目标过拟合） |
| 游走预算 | num_walks=2 / walk_length=48 优于 num_walks=10 / walk_length=40 等更「大」的配置；继续加数据无增益 |
| window | window=5 明显优于 10、20（更长的窗口引入跨社群噪声） |
| 嵌入维度 | 32 / 64 / 128 差异在 ±0.005 内 |
| 分类器正则 C | C=0.001 明显优于 C=1（标准化后高方差坐标会带偏方向） |
| 行 L2 归一化 | 归一化后 AUC 稳定高于未归一化约 0.01 |
| 图类型 | 在 LFR（mu=0.15/0.35/0.45、平均度 5/6/10）上，本系统与 Katz 的差距在 **-0.007 ~ +0.020** 之间，**达不到 0.03 门槛**；在 SBM 与真实图 karate 上差距分别为 +0.0375 / +0.1082 |

**诚实结论**：node2vec 相对强全局启发式（Katz）的优势是**图相关**的，不是普适的。本卡只声称在已实测的两个基准上达标；在 LFR 同配图上二者基本打平。原因可解释为：Katz 是对全部路径长度的加权求和，而 node2vec 等价于对「窗口截断的游走共现矩阵」做低秩分解，二者在同配图上信息高度重合。

### 5.1 可扩展性对照（n=1k / 5k / 20k，2GB 内存预算；node2vec 关 HPO 固定配置）

| n | node2vec AUC | katz AUC | node2vec 耗时 | katz 耗时 | 峰值内存(理论) | 2GB 可行性 |
|---|--------------|----------|---------------|-----------|----------------|------------|
| 1k | 0.6561 | 0.6573 | 13.3s | 1.3s | ~0.01 GB | ✅ 可行 |
| 5k | 0.6000 | 0.6034 | 16.0s | 6.4s | ~0.37 GB | ✅ 可行 |
| 20k | — | — | — | — | ~5.96 GB | ❌ 不可行（实测单 n×n float64=2.98GB 已超 2GB） |

- **2GB 断裂点（裁定「待实证确认」项已坐实）**：本系统用 `(n, n) float64` 稠密邻接，2GB 预算下设计边界约 **n≈16k**（2GB / 8B / 2 矩阵）。n=20k 时稠密表示 + Katz 稠密求解共需 ~5.96GB，实测单矩阵即 2.98GB 超出预算 → node2vec 与 Katz **均不可行**。
- n≤5k 二者 AUC 基本持平（ΔAUC ≈ 0，同配图信息重合）；开启 HPO 偏置后 node2vec 在基准上反超 Katz（见第 2 节）。
- 实跑脚本：`python examples/scalability_study.py`。

## 6. 防泄漏与评测协议

- train / valid / test = 70% / 10% / 20% 的**正边**，另配等量负样本；
- valid + test 正边在训练图中被**物理删除**（重建邻接矩阵，不是掩码）；
- 负样本从「非全集正边」中采样，不会把真实边误标为负类；
- 训练图保持连通（生成森林边强制留在训练集）；
- 标准化器只在训练折 fit；启发式特征全部基于训练图计算；
- HPO 目标函数只用 valid 折 AUC，test 折全程不参与。

## 7. 适用范围与限制

**适用**：中小规模无向图的链接预测；离线 / 无 GPU / 无外网环境。

**不适用 / 限制**：
1. **稠密邻接 O(n²) 内存**：邻接矩阵用 `(n, n) float64` 稠密存储，2GB 预算下设计边界约 **n≈16k**（2GB / 8B / 2 矩阵）。实测 n=1k / 5k 可行（峰值 ~0.01 / ~0.37 GB）；**n=20k 实测单 n×n float64 矩阵即 2.98 GB，已超 2GB → 不可行**（见第 5.1 节）。若要上更大图需改稀疏表示。
2. 未支持带属性图、异构图、动态图；
3. **Katz 裁定（reference 基线）**：Katz 属「补充参考基线」，不属 node2vec 论文口径公平基线族（arXiv:1607.00653 Table 3/4 基线集合不含 Katz；其信息集为全路径计数，超出邻域集）。在合成同配图上本系统与 Katz 基本打平（ΔAUC ≈ 0，见第 5 节），若业务图属此类，应把 Katz 作为并列方案而非被超越对象。裁定来源与待复核声明见 `../spec/baseline_ruling.md`。
4. 小图（如 karate）测试集仅十几条边，AUC 标准差可达 0.05，结论统计效力有限。

## 8. 复现

```bash
python examples/run_demo.py            # 5 seeds × 2 场景，落盘 benchmark.json
python -m pytest -q                    # 单测
python -m graphforge.cli run --tier1-only --graph karate   # 离线兜底路径
```

同 seed 两次运行的 AUC / AP / 参数**逐位一致**（只有 wall-clock 耗时不同）。
